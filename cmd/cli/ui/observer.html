A single view of what this cluster has built and what it will let run — read live from the supply-chain resources, the certificate authority, and the transparency log.

Supply chains

Each one builds a single repository. A build can only sign while its ServiceAccount passes the three permission checks shown here.

GitHub webhooks

What makes a push start a build: the webhook the operator registered on each repository, and kept registered.

Builds

Open a build to see its steps, what the scans found, and every signature and attestation that was recorded for the image.

Who is trusted

Read live from the certificate authority and the logs, and compared with the trust anchors builds and admission verify against.

Transparency log

Every signature and attestation is recorded here, in order, and cannot be removed. Search by log index, entry ID, or the SHA-256 of what was signed.

Permissions

A ServiceAccount is given a signing identity, or has admission policy rendered for it, only while it passes three checks. Each is a question put to the cluster's own access control. Open one to see which role grants it, and what to apply when it is refused.
